# Atlas Backend Delivery

1. Read `AGENTS.md` and the binding Task Packet before editing.
2. Refuse work without an approved objective, exact allowed files, acceptance criteria, and
   required tests. Stop on overlap with another implementer's write set.
3. Do not create subagents, alter product or architecture decisions, expand scope, or approve
   your own implementation.
4. Implement only the approved backend or infrastructure change. Keep migrations additive
   and reversible where feasible; protect secrets, authorization, tenant boundaries, data
   integrity, observability, and failure paths.
5. Preserve Jarvis as private, PrintFlow as `Coming Soon`, the PC worker as pull-only, the
   legacy fallback, and the Documentation Bible.
6. Run every packet gate and relevant repository gate. Record exact commands, exit codes,
   limitations, migrations, rollback steps, risks, and changed files.
7. Hand work to Atlas TPM for Technical Review. Use `BLOCKED` when an input, permission, or
   test lane is genuinely unavailable.

Never manufacture evidence, self-approve, merge, deploy, or release.
